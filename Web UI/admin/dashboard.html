HARDWARE & TRANSMISSION CONFIGURATION GUIDE

1. WiFi Fallback Configuration

  • The device primarily sends data over the SIM / GSM network.
  • It needs active SIM load (data credits) FIRST so it can reach the cloud and retrieve the WiFi credentials saved in this panel.
  • Once the SSID & password are fetched, the device uses WiFi as a fallback when the GSM signal is weak or unavailable.
  • NOTE: Only 2.4GHz networks can be connected — 5GHz networks are not supported by the module.

2. Sensor Calibration Offsets

  • Temperature (°C) - BME280: Adjust for internal board heat (e.g., -2.0 if the board sits inside an enclosure).
  • Adjustment - JSN-SR04T: Fine-trim after comparing the dashboard water level with a real staff gauge (device allows +/-100 cm).

3. Sensor-to-Ground Distance

  • Total distance from the sensor face to the dry ground. Mount the sensor at least 25 cm above the highest expected water - the JSN-SR04T has a 25 cm blind zone and cannot measure anything closer, so a lower mount loses readings exactly when flooding starts.
  • Device range: 50-1000 cm.
  • Used to convert the sensor reading into actual water depth (Depth = Distance to Ground − Sensor Reading).

4. Reference Baselines

  • Max Clear Lux: Peak brightness at noon on a clear sunny day; detects cloud cover and approaching storms.
  • Base Pressure: Standard sea-level pressure for your elevation; pressure drops signal incoming rain.

5. Model Calibration (defines the 0–10 flood risk score)

  • Z-R Relationship (R = aZ^b): Standard meteorological formula for rainfall intensity.
    • 'a' constant: Typically 200 (steady rain) to 300 (tropical storms).
    • 'b' constant: Typically 1.6. Lowering it makes the model more sensitive to heavy rain.
  • Prediction Weights (should total 100%):
    • Pressure: High weight enables "anticipatory" warnings before it rains.
    • Humidity: Weights the saturation level of the atmosphere.
    • Light: Proxy for cloud cover; drops during storm entry.
    • Rain: Weighted "reactive" reporting of the actual rain sensor data.
  • Tuning these lets the network adapt to your city's specific climate.

ALERT COMMAND CENTER GUIDE

How the Three-Tier System Works

  • The device checks every sensor reading against Level 1 → Level 2 → Level 3 and fires the highest level matched.
  • A higher level always overrides the cooldown of a lower one, so escalation is never delayed by a quieter alert that fired earlier.
  • Each level sends its own SMS broadcast to every registered subscriber and shows up in the dashboards with its own color.

1. Total Rain (mm)

  • The running rainfall total for today. When it reaches this value, the level triggers.
  • It resets automatically at midnight, so it always measures the current day's accumulation.
  • Higher level = more rain required (e.g. 20 mm for Advisory, 50 mm for Warning, 100 mm for Emergency).

2. Water Rise (cm/min)

  • How many centimeters the river/water level climbs per minute. Start with 0.5 (Advisory), 1.0 (Warning), 2.0 (Emergency) and calibrate with site data.
  • A fast rise triggers the level even without heavy rain — this is the earliest flood signal upstream.

3. Rain Intensity (mm/h)

  • The instantaneous rain rate right now (how hard it is raining at this moment).
  • Optional override: if the rain gets this intense, the level fires immediately without waiting for the daily total.

4. Water Level (cm)

  • The absolute water depth. Reaching it forces the level immediately.
  • Set to 0 to disable this trigger and rely on the other thresholds.
  • Max measurable: 175 cm (sensor height − 25 cm blind zone).

5. Broadcast Messages

  • The SMS text sent to all subscribers when that level fires — keep it short and actionable.
  • Maximum 133 characters (the SMS limit after adding the alert header).

6. Manual Send & Save

  • Send L1/L2/L3 SMS Manually: dispatches that level's message to all subscribers right away, without waiting for a trigger — useful for drills and direct announcements.
  • Save Alert Levels & Messages: persists every threshold and message to the cloud. The device picks up the new settings on its next sync — no reflash needed.

SYSTEM BEHAVIOR GUIDE

Apply System State

  • Saves everything in this panel at once — cooldowns, maintenance mode, history cadence, and the Rate Computation settings below. The device picks it up on its next config sync (seconds on Wi-Fi, ~30 s on cellular).

1. Alert Cooldown (hours)

  • Minimum time between two automatic SMS broadcasts of the same level.
  • A higher alert level always overrides the cooldown — escalation is never delayed.
  • Recommended: 5 hours (the default). Use 1–2 h only if you want more frequent same-level updates during long storms.

2. Maintenance Mode

  • Suspends all automatic SMS alerts for drills, maintenance, or testing — telemetry keeps flowing to the dashboards.
  • Manual sends from the Alert Command Center still work while maintenance is on.
  • Recommended: OFF. Switch on only for sensor work, drills, or planned downtime — and back off right after.

3. History Cadence (min)

  • How often a snapshot is written to the weather_history archive (default 60).
  • Alert escalations always log immediately, no matter what this is set to.
  • Recommended: 60 minutes (the default). 15–30 min gives finer history graphs but grows the archive 2–4× faster.

4. Rate Computation — Units

  • Rain Unit (mm/h | mm/min): the unit the rain rate is reported and displayed in. Rain-intensity thresholds are always compared in canonical mm/h.
  • Rise Unit (cm/min | cm/h): the unit the water-rise rate is reported and displayed in. Rise thresholds are always compared in canonical cm/min.
  • Threshold values are always stored in the canonical units (rain mm/h, rise cm/min) — the admin inputs and both dashboards convert automatically, so a threshold of 1 always means 1 cm/min no matter which unit you display.
  • Recommended: keep the defaults mm/h + cm/min. Switch to per-minute units only if your team reports in those terms — and re-read the thresholds after switching.

5. Rate Computation — Sliding Windows

  • Rain Window (5/10/60 min): how much tip history the rain rate averages. Longer = smoother and calmer; shorter = snappier peaks.
  • Rise Window (5/10/60 min): how far back the level change is measured. Longer = steadier numbers; shorter = faster reaction.
  • Rise Smoothing (1/2/5 min): running average that cancels surface waves before the rate math sees them.
  • Recommended: Rain 10 / Rise 5 / Smoothing 2 (the defaults — balanced). Calmer numbers during long storms: Rain 10 / Rise 10 / Smoothing 5. Fastest flash-flood reaction: Rain 5 / Rise 5 / Smoothing 1.
  • Important: a longer window makes the same burst read as a smaller rate (e.g. a +30 cm surge reads ~5.8 cm/min on a 5-min window but only ~0.5 cm/min on a 60-min window). So if you leave the window changed permanently, re-tune your Water Rise thresholds from your site's real history on that window — keep the defaults unless you have a reason to switch.

6. Changing Units or Windows

  • When you change any unit, window, or smoothing setting, the device clears its rate histories so no data mixes between schemes (logged as RATE_SCHEME in the System Logs).
  • Re-warming takes as long as the longest window you chose. Daily rain totals and GPS are never touched by this reset.

7. Reset Sensor Data

  • Zeroes the tipping-bucket data (daily rain, tips, rain rate) and clears the ultrasonic rise history on the device — one click, no reflash.
  • Use it after phantom tips, EMI glitches, or to re-baseline during testing. GPS and alert state are never touched.
  • Recommended: use sparingly — after phantom-tip bursts or EMI glitches, never during a real flood (it wipes today's rain total mid-event).
  • Every reset is logged to the System Logs terminal (SENSOR_RESET) with the amount of data that was cleared.
